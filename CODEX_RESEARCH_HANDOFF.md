# Codex Cloud — Thesis research handoff and completion protocol

## Objective and authority
Master's thesis: AI-Assisted Decision-Support Framework for Disaster Relief Resource Allocation Under Uncertainty.
Continue the empirical research from Phase 50 through a defensible conclusion. Respect environment permissions. Request help only for genuinely blocking permissions, missing data, budget or decisions outside this scope.

## Execution, stopping rules, and handoff
- Start by recording git SHA, data inventory, artifact availability, reproducibility checks, frozen Track A checksums and plan in research/STATUS.md; keep an append-only research/EXPERIMENT_LOG.md with objectives, inputs, code SHA, seed, splits, metrics, errors and negative results. Use resumable scripts and checkpoints, bounded retries, no unbounded loops or massive downloads. Commit substantive checkpoints to a research branch if authorized; otherwise save patch and status. Run local unit/smoke tests before expensive Actions. Do not retry failed calls indefinitely. If limits hit, checkpoint exact next command and remaining work.
- Aim for a finite conclusion, not endless experiments. For each major hypothesis use a predeclared primary metric and maximum reasonable number of variants; stop when evidence is sufficient or source/validation/coverage limits make it unjustified. Don't force a positive result. After Phase50 prioritize scale, independent validity and operational availability rather than repeatedly tuning the 59 examined test cases.
- Continue routine work autonomously within allowed scope; stop for required approval or exhausted usage/access. Do not circumvent sandbox or quota restrictions. If a truly independent dataset cannot be obtained, finish with a transparent negative/inconclusive conclusion and future-work plan.
- Final deliverables: research/FINAL_CONCLUSION.md, research/FINAL_METRICS.csv, research/SOURCE_AND_FEATURE_MANIFEST.csv, reproducible scripts/workflows, final human-readable Jupyter notebook (steps, mathematical and technical explanations, actual figures, metrics, limitations), and experiment logs. Include a thesis-ready methods/results/discussion/limitations draft and a clear separation of accepted results, exploratory evidence, rejected variants and untested proposals. Include data licenses/links and actual run/commit IDs. Avoid invented references, claims of verified disaster-specific flooding, real-time deployment, or causal allocation benefit unless supported.
- Acceptance: original Track A untouched; Phase50 actually executed or explicitly blocked with evidence; independent validation/coverage and timing audit completed to reasonable feasible extent; final predictive tests only if justified; final synthesis and runnable reproducibility instructions; all gaps documented. Final conclusion may legitimately be that current enrichment does not improve the frozen method or is not sufficiently validated.
